# Folduo SM-F966Q 非公式試験版

元のコード: https://github.com/bunkaich/Folduo
基準コミット: c9e5976cf1d5176652fcf0fc984bb5ec86751d29 (v0.1.21)
試験版バージョン: 0.1.21-q1

## 現在の状態

SM-F966Qを起動候補に追加した試験版です。Qでの動作確認はまだ行っていません。
型番の一致は互換性の証明ではありません。必要なSamsungの画面状態や内部API、
指定純正壁紙が端末に存在しない場合は動作しません。
作者の実機確認条件はSM-F966Z / Android 16 / One UI 8.5です。

## 変更内容

- アプリの起動判定、画面制御判定、壁紙補助ツールにSM-F966Qを追加。
- 型番リストをDeviceModelsに共通化。Z/Q以外は拒否。
- 画面状態の名前と属性の検証、競合検出、停止時の制御解除は維持。
- 壁紙の上書き防止、呼出し元権限チェック、保護画面の除外は維持。
- センサー診断にモデル番号・Androidバージョン・ビルド番号を表示。
- アプリ名と説明で非公式試験版であることを表示。
- GitHub ActionsによるAPKと壁紙補助ツールのビルドを追加。

## ビルド

この一式を自身のFolduoフォークへ反映すると、mainへのpushまたはActionsの手動実行で
「Build Folduo Q Experimental」が動きます。成功後、Artifacts内の
「Folduo-0.1.21-q1」をダウンロードして展開してください。
APK、壁紙設定ZIP、SHA256SUMSが含まれます。

ローカルの場合は元のREADMEのJDK17・Android SDK環境を用意し、次を実行します。

```sh
./gradlew :app:assembleRelease :app:testDebugUnitTest :app:lintRelease
python3 tools/build-wallpaper-helper.py
```

元の作者のAPKとは署名が異なります。既にFolduoがある場合はアプリ内で停止してから
アンインストールして導入してください。設定は引き継がれません。
本ワークフローは実行環境のデバッグ署名を使うため、再ビルド時にも署名が変わり得ます。
アプリIDは元のFolduoと共通で、両方を同時にインストールする構成にはしていません。

## 初回確認

1. 他の折りたたみ画面制御アプリを停止します。
2. APKをインストールし、Shizukuを起動してFolduoから接続します。
3. アニメーション開始前にセンサー診断を実行し、診断表示を確認します。
4. 画面制御欄に状態が利用できない、メソッドが見つからない等のエラーが出る場合は、
   その表示と「設定→端末情報→ソフトウェア情報」のOne UIバージョンを共有してください。
5. 対応する純正壁紙を設定します。元のREADME.ja.mdの手順を参照してください。
   カバー側の設定には同梱のQ対応壁紙補助ツールを使います。
   最初に `python3 cover-wallpaper.py status` で読み取り確認してから
   `python3 cover-wallpaper.py apply` を実行します。PC側にPythonとADBが必要です。
6. 重ねて表示・通知を許可し、画面アクセスの説明を読んでアニメーションを有効化します。
7. ロック解除した状態で一度完全に閉じ、電卓などでゆっくり開閉を試します。

不調時はカバー画面からFolduoの停止ボタンを押します。操作できない場合は端末を再起動し、
Shizukuを再開する前にFolduoの有効化設定を停止してください。
アンインストール前にもアプリ内の停止操作が必要です。壁紙は別途設定から戻してください。

## 検証範囲

ローカルでXML・Python・ワークフローYAMLの構文と差分形式を確認済み。
JavaコンパイラとAndroid SDKがなく、依存配布先にも接続できないため、
APKビルドとJava単体テストは未実行です。型番判定の単体テストはActions実行用に追加しています。
Actionsでビルド・単体テスト・lintが成功しても、Qの実機検証は別途必要です。
